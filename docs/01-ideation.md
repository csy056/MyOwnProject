# 01. 아이데이션

> 상태: 1차 방향 확정 (2026-10-16)

## 확정된 방향

| 항목 | 결정 |
| --- | --- |
| 플랫폼 | 모바일 앱 (Android / iOS) |
| 장르 | 무너진 서울을 배경으로 한 생존 텍스트 RPG (서울2033 모티브) |
| 핵심 루프 | 스토리 분기 중심: 선택 → 결과 → 상태 변화 → 다음 선택, 다중 엔딩 |
| 차별점 | 플레이어가 실제로 있는 위치에 맞춰 시작 거점과 이벤트가 달라지는 **위치 적응형 스토리** |
| 수익 모델 | 무료 + 광고/인앱 결제 |
| 세계관 | **돔**: 어느 날 서울 전역이 정체불명의 벽에 둘러싸여 바깥과 끊겼다 |
| 서울 밖 유저 | 외부인 시작 루트: 벽 바깥에서 서울로 들어오는 사람으로 시작한다 |
| MVP 위치 기능 | L1 시작 거점, L2 지역 이벤트, L3 지역 발견, L4 실제 밤낮 연동 (전부 포함) |
| 개발 방식 | 기획과 스토리 방향은 오너가 정하고, 코드는 Claude가 구현한다. 스토리는 코드 없이 글로 쓸 수 있게 설계한다 |

### 세계관: 돔

```
  벽이 생긴 지 412일.
  바깥에서는 아무도 오지 않았다.
  너를 빼고.
```

- **생존자 루트:** 서울 안에서 접속하면 벽 안에 갇힌 생존자로 시작한다. 실제 위치 근처의 역이나 구가 첫 거점이 된다.
- **침입자 루트:** 서울 밖이나 해외에서 접속하면 벽 바깥에서 안으로 들어오는 첫 번째 사람이 된다. 접속 위치가 곧 설정이 된다.
- **메인 미스터리:** 벽은 무엇인가. 누가, 왜 세웠는가.
- **엔딩 축:** 탈출 / 잔류 / 벽의 진실

### 한 줄 피치 (초안)

> 지금 당신이 서 있는 그 동네가, 무너진 서울의 첫 번째 생존지가 된다.

## 레퍼런스: 서울2033

- 핵전쟁으로 폐허가 된 서울을 배경으로 한 텍스트 로그라이크 게임이다. 선택에 따라 능력과 보상을 얻거나 상처와 스트레스를 입고, 그 결과가 다음 모험으로 이어진다.
- 텍스트와 삽화가 중심이고, 스크린리더와 보이스오버를 지원한다.
- 구글 인디게임 페스티벌 톱3에 올랐다.

| 가져올 것 | 피할 것 |
| --- | --- |
| 텍스트와 최소한의 삽화로 상상력을 끌어내는 연출 | 원작의 세계관, 고유명사, 사건을 그대로 쓰는 것 (IP 문제) |
| 선택의 결과가 상태로 누적되는 구조 | "핵전쟁 후 서울"이라는 설정을 그대로 쓰는 것 |
| 접근성 지원 (스크린리더) | 로그라이크 반복 구조 (우리는 스토리 분기 중심) |

**차별화 축:** 독자적인 세계관, 스토리 분기와 다중 엔딩, 위치 적응형 진행

## 위치 적응형 설계 초안

### 원칙

1. **정밀 좌표는 기기 밖으로 보내지 않는다.** 기기 안에서 "자치구"나 "가장 가까운 역" 단위로 바꾼 뒤 좌표는 버린다.
2. **위치 권한이 없어도 끝까지 플레이할 수 있어야 한다.** 권한을 거부하면 시작 지역을 직접 고르는 경로를 준다.
3. **플레이 중 이동을 강요하지 않는다.** 걸으면서 화면을 보게 만드는 설계는 안전 문제가 있다.

### 반영 단계

| 단계 | 내용 | 난이도 |
| --- | --- | --- |
| L1 시작 거점 | 가장 가까운 지하철역이나 구가 첫 은신처가 된다 | 낮음 |
| L2 지역 이벤트 | 구마다 랜드마크를 바탕으로 한 고유 이벤트가 있고, 공통 이벤트에는 지명을 치환해 넣는다 | 중간 |
| L3 지역 발견 | 다른 지역에서 앱을 켜면 그 지역의 거점이나 기록이 해금된다 | 중간 |
| L4 시간 연동 | 실제 낮과 밤에 따라 위험도와 이벤트가 달라진다 | 낮음 |

### 콘텐츠 분량 전략

25개 구마다 고유 스토리를 쓰면 분량이 감당할 수 없을 만큼 커진다. 그래서 다음처럼 나눈다.

- **공통 이벤트 풀 + 지역 태그 + 지명 템플릿**
  예: `{역이름} 승강장 끝, 꺼진 전광판 아래에 누군가 있다.`
- **고유 이벤트**는 MVP에서 3~5개 구만 만들고, 나머지 구는 업데이트로 늘린다. 이렇게 하면 지역 확장팩이 자연스럽게 수익 모델로 이어진다.

### 데이터 출처 후보

- 서울 지하철역 좌표와 행정구역 경계: 공공데이터포털, 서울 열린데이터광장
- 앱에 데이터를 내장해 외부 지도 API 없이 오프라인으로 동작하게 한다.

## 수익 모델 초안

| 구분 | 상품 | 비고 |
| --- | --- | --- |
| 보상형 광고 | 사망 시 마지막 선택으로 되감기, 보급품 추가 | 광고 시청은 언제나 선택 사항 |
| 인앱 결제 | 광고 제거 | |
| 인앱 결제 | 지역/스토리 확장팩 | L2 지역 이벤트와 연결 |
| 인앱 결제 | 후원 팩 | 크레딧 등재 등 |

**원칙:** 돈을 내야 스토리를 진행할 수 있게 만들지 않는다. 스토리 게임에서 결제로 진행을 막으면 반감이 크다.

## 리스크와 확인할 것

- **위치정보법:** 위치기반서비스사업 신고 대상일 가능성이 높다. 신고하지 않고 운영하면 형사처벌 조항(3년 이하 징역 또는 3천만 원 이하 벌금)이 적용될 수 있다. 출시 전에 방송미디어통신위원회 신고 절차와 소상공인 유예 규정을 법령 원문으로 확인한다.
- **스토어 심사:** 위치 권한을 쓰는 목적을 설명하는 문구와 권한을 거부했을 때의 대체 동작이 필요하다.
- **실존 지명과 상표:** 지명은 사용해도 무방하지만, 실존 기업이나 건물 브랜드명은 일반 명사로 바꾸는 방안을 검토한다. (예: "123층짜리 타워")
- **MVP 분량:** L1~L4를 모두 넣기로 했으므로, L2 고유 이벤트는 3~5개 구로 제한해야 일정이 지켜진다.
- **원작과의 유사성:** 세계관과 고유명사는 처음부터 독자적으로 설계한다.
